# タクソノミーアーカイブ並び替え設定

## 目的

カテゴリー・タグ・カスタムタクソノミーの各ターム編集画面に、そのタームのアーカイブページだけに適用する投稿一覧の並び替え設定を追加する。

既存の「サイトデザイン拡張 > アーカイブ > 並び順」はサイト全体の設定として維持し、ターム個別設定がない場合のフォールバックとして使用する。

## 対象範囲

- カテゴリーアーカイブ
- タグアーカイブ
- 公開され、管理画面を持つカスタムタクソノミーのタームアーカイブ
- フロントエンドのメインクエリのみ

管理画面の記事一覧、検索結果、投稿タイプアーカイブ、日付アーカイブ、サイドバーなどのサブクエリには、ターム個別設定を適用しない。

## 設定UI

ターム編集画面の「yStandard Toolbox 設定」に「一覧表示設定」セクションを追加する。

### 並び順の基準

- `-（全体設定に従う）`
- `公開日`
- `更新日`
- `タイトル`
- `ランダム`

### 順序

- `降順`
- `昇順`

「ランダム」を選択した場合、順序は結果に影響しないため、順序UIを非表示または無効化する。あわせて「ランダムでは昇順・降順は適用されません」と説明する。

初期値は「-（全体設定に従う）」とし、タームメタを保存しない。

## 保存形式

設定値はタームメタとして分けて保存する。

| メタキー | 許可する値 | 未設定時 |
| --- | --- | --- |
| `ystdtb-archive-orderby` | `date` / `modified` / `title` / `rand` | 全体設定に従う |
| `ystdtb-archive-order` | `ASC` / `DESC` | `DESC` |

`ystdtb-archive-orderby`が空の場合は両方のメタを削除する。「ランダム」の場合は`ystdtb-archive-order`を削除し、クエリには`order`を指定しない。

保存時はnonceと`edit_term`権限を確認し、許可リストにない値は保存しない。入力値は`wp_unslash()`後にサニタイズする。

## 設定の優先順位

タームアーカイブでは次の順で設定を決定する。

1. 対象タームの個別設定
2. 既存の全体設定`archiveOrder`
3. WordPressまたはyStandardの既定値

タームメタに不正値が残っている場合は個別設定を無効として扱い、全体設定へフォールバックする。

## 実装方針

### UIと保存

並び替えはアーカイブ表示の責務なので、`Archive`クラスから既存の`ystdtb_term_edit_form`と`ystdtb_term_edit_save`へコールバックを登録する。`Taxonomy`クラスは設定セクションのコンテナ、nonce検証、保存フックの実行を担当する既存構成を維持する。

今回の設定はWordPress標準のメインクエリだけを変更するため、yStandard以外のテーマでも利用可能とする。そのため、ターム設定コンテナはテーマ判定だけで非表示にしない。既存のSEO・ヘッダーオーバーレイ設定は、各機能側でyStandard環境の場合だけ登録する。

### クエリ変更

`Archive`クラスの`pre_get_posts`は、全体設定の有無にかかわらず登録する。現在は`archiveOrder`が設定されている場合だけ登録されるため、ターム個別設定だけがあるケースを処理できない。

コールバック内では、渡された`WP_Query`の条件メソッドを使い、管理画面とメインクエリ以外を早期終了する。

- タームアーカイブではターム個別設定を先に解決する
- 個別設定がない場合は既存の全体設定を使う
- タームアーカイブ以外のアーカイブと検索結果では、従来どおり全体設定だけを使う
- `rand`以外は`orderby`と`order`を設定する
- `rand`は`orderby`だけを設定する

全体設定は既存の`orderby/order`形式を維持する。タームメタと全体設定を同じ内部形式へ正規化する小さなメソッドを`Archive`クラス内に置き、クエリ変更処理を重複させない。

## 選択肢の判断

初期対応には「更新日」を追加する。既存の全体設定と記事一覧ブロックにも同じ選択肢があり、リライトした記事を新しい順に表示する用途が明確なため。

次の値も`WP_Query`では利用できるが、初期対応には含めない。

| 候補 | 初期対応に含めない理由 |
| --- | --- |
| `menu_order` | 多くの投稿では値がすべて`0`で、投稿タイプ側に並び順を入力する仕組みがないと結果が分かりづらい |
| `comment_count` | コメントを使わないサイトでは意味がなく、人気順としても閲覧数とは一致しない |
| `ID` / `author` / `slug` / `parent` / `type` | 一般的なアーカイブ表示の用途が限定的 |
| `meta_value` / `meta_value_num` | メタキー、値の型、未設定投稿の扱いを追加で設計する必要がある |

`menu_order`またはカスタムフィールド順が必要になった場合は、投稿タイプごとの適用条件と同順位時の第2ソートキーを含む別機能として追加する。

## ランダム表示の注意

ランダム表示はページを読み込むたびに結果が変わる。ページ送りを行うと投稿の重複や未表示が起こり得るため、設定UIに注意書きを表示する。投稿数が多いサイトでは通常の並び順よりクエリ負荷が高くなる可能性もある。

## テスト方針

PHPUnitで次を確認する。

- ターム個別設定が全体設定より優先される
- 個別設定がない場合は全体設定へフォールバックする
- 個別設定と全体設定がない場合はクエリを変更しない
- カテゴリー・タグ・カスタムタクソノミーで個別設定が適用される
- 検索結果や投稿タイプアーカイブにはターム個別設定を適用しない
- 管理画面とメインクエリ以外を変更しない
- 許可リスト外の保存値を拒否する
- 「全体設定に従う」でタームメタを削除する
- ランダムでは`order`を設定しない
- yStandard以外では一覧表示設定だけが表示され、yStandard専用設定が混ざらない

手動確認では、保存後の再読み込み、公開日・更新日・タイトルの昇順と降順、ランダム表示、全体設定への復帰を確認する。
