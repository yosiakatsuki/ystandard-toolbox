# FAQ親ブロックのスタイル設定

## 対象範囲

v2.4.0向けの親FAQのスタイル設定と、v2.3.0以前の形式からの移行を対象とする。`core/details`などとの相互変換は行わない。子のラベル設定などの残作業は`../faq-item/DESIGN.md`で管理する。

レスポンシブ入力部品と通常値・端末別値・リセットの契約は[共通設計](../../../../docs/block-style-controls.md)を参照する。

## 標準設定と独自設定

- 背景色・グラデーション・枠線・タイポグラフィ・余白はWordPress標準のBlock Supportsを使う。プリセット用の標準属性は維持する
- レスポンシブ文字サイズと余白は`style.ystdtb.faq.responsive`へ保存する
- 開閉ボタン色は`style.ystdtb.faq.arrow.color.text`、余白は`style.ystdtb.faq.arrow.spacing.margin`へ保存する
- 色のプリセットは`var:preset|color|{slug}`、カスタム色はCSSカラー値とする
- `isAccordion`は動作の属性として維持し、OFFにしても設定済みの色と余白は削除しない

## 親子同期とリセット

親の開閉ボタンUIから変更すると、Q/Aの`style.ystdtb.faqItem.arrow`にも対象の色または余白を同期する。子ごとのstyleを基準にマージし、本文・背景・ラベルなどを保持する。

色と余白のリセットはそれぞれ独立させ、空になった階層は削除する。子のデザインサンプルが設定する開閉ボタン色も新保存先へ変更する。デザインサンプルは従来どおり対象Itemへ適用し、親・他方のItemは変更しない。

旧色属性に関する未使用のContext定義と`withColors`への依存を除去する。フロントの開閉処理と主要クラス、Q/A構造は変更しない。

## 旧形式からの移行

- v2.3.0とv1.34.1以前の旧saveを維持し、それぞれのmigrateから現行形式へ直接変換する
- 旧背景・枠線に加え、`accordionArrowColor`と`customAccordionArrowColor`を親子それぞれの新保存先へ移し、移行結果から旧色属性を除去する
- 親やA側は色が保存HTMLに現れないため、`isEligible`で旧色属性の存在を検出し移行する
- 新形式の色が既にある場合は保持する。旧形式のプリセットとカスタム値が併存する場合は旧表示と同じくプリセットを優先する
- 移行時は親子の保存値を個別に保持し、親の色で子の色を一律に上書きしない
- v2.4.0開発途中の形式に対してdeprecatedは追加しない

## 検証

- unit：プリセット・カスタム色の親子同期、色リセットでの他設定保持、空階層の除去
- integration：新形式の保存と再読込、旧色の移行、旧新設定の併存、Q/A・本文の保持
- fixture：v2.3.0の旧入力は保持し、現行プリセット・色設定の期待値を新形式へ更新する
- 実サイト：v2.3.0サイトで保存した投稿HTMLを開発サイトへ読み込み、移行後の表示・保存再読込・開閉動作・色の変更とリセットを確認する
- 関連lint・ブロックbuild・`git diff --check`を実行する

実行結果は本書の仕様と分け、`test-results/operation.md`へ記録する。
